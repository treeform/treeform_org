Publishing treeform.org

This is a static site. The files in the repository root are the website.
There is no package installation or build step.

Preview locally

From this directory, run:

  python3 -m http.server 8000

Open http://localhost:8000 in your browser. Use an HTTP server so Silky's
WebAssembly demos can load their .wasm and .data files.

GitHub Pages

Repository: https://github.com/treeform/treeform_org
Website: https://treeform.org/

Pages publishes the main branch from /(root). Keep the empty .nojekyll
file to publish static files directly. Push commits to main to publish
updates. No custom Actions workflow or build tools are required.

Domain configuration

GitHub Pages uses treeform.org as its custom domain. Keep the root CNAME
file in the repository. The original GitHub Pages URL redirects here:
https://treeform.github.io/treeform_org/

Cloudflare DNS is configured with these DNS-only A records for @:
   185.199.108.153
   185.199.109.153
   185.199.110.153
   185.199.111.153
The DNS-only CNAME for www points to treeform.github.io. Leave all five
records DNS-only so GitHub can validate the domain and issue certificates.

After DNS changes, allow cached lookups to expire. GitHub may take up to
an hour to provision HTTPS. If certificate provisioning does not start,
remove and re-add the custom domain in Settings > Pages, as described in
GitHub's troubleshooting guide. Enable Enforce HTTPS once it is available.
Pull main after changing the custom domain to sync GitHub's CNAME commits.

The CNAME file alone does not configure DNS. GitHub's current custom-domain
guide is linked below. Existing 404 links use the GitHub Pages URL, which
redirects to the custom domain.

Add a project or static files

Create a directory such as project-name/ and put its index.html and assets
inside. It will be served at https://treeform.org/project-name/. Other static
files can be stored at any path and linked directly.

The homepage has separate Games, Libraries, and Videos sections, in that
order. To add a library, copy a project article inside the libraries section
in index.html.
Update its name, description, destination, repository owner, and category.
Keep the description in the title, data-search, and screen-reader text.
Give the description a unique ID and update aria-describedby to match.
Use the repository's hero image when it has one. Store the original image
in assets/libraries/, record its source in sources.json and NOTICES.txt,
and retain the upstream license in assets/libraries/licenses/. Copy an
existing project-with-art article and update its image and dimensions.
For libraries without hero artwork, add an icon to assets/icons.svg and
reference that symbol with the project tile's use element. Move articles
to change their order.
Supported library categories are graphics, interfaces, networking, data,
and tools. Search and category filters affect only the Libraries section.
The catalog is ordinary HTML and remains readable without JavaScript.

Each library card shows its GitHub star count next to its category. Counts
are saved in the HTML and assets/libraries/stars.json. To refresh them,
sign in to the GitHub CLI and run:

  node tools/update_stars.mjs

The command fetches all counts in one GitHub query. Commit and push the
updated files to publish them. New cards need a project-stars span with
data-repo set to owner/repository. Visitors do not need to contact GitHub
to see the counts. Hover over a count to see its last update date.

To add a game, copy a game article inside the games section. Update its
name, description, link, and artwork. Keep game images in assets/games/
and record their source in assets/games/NOTICES.txt.

Use relative asset and page links so the site can also work at a GitHub
Pages repository URL if the custom domain is removed.

Update the videos

The homepage lists talks and channel videos as static links, newest first.
Copy a video-card link inside the video-grid to add another video. Update
its YouTube URL, title, duration, and image. Save the original thumbnail
in assets/videos/ and add its source to assets/videos/NOTICES.txt.
The page uses local thumbnails and needs no YouTube API key or video player.

Update the Silky demos

The .js, .wasm, and .data files in silky/demos/ are prebuilt Silky examples.
Keep each demo's three files together and replace them as a matching set.
The .html wrapper loads them without a backend or special server headers.
